# ドメインの複数帰属と関係図

## 要求
「ドメイン関係図を見たい」「複数ドメイン帰属出来ていい」「セレクトボックスで複数選択が正しい」。

## 動作
- PF-DR-1: コアの展開内で複数のビジネスドメインを選択し、一括追加できる。他のコアに所属済みでも選択可能。同じコアに所属する項目は候補から除く。
- PF-DR-2: `domain_memberships` にコアとビジネスの多対多関係を保存する。既存parent_idを上書きしない。旧コア→ビジネスの親子関係は所属として引き続き表示する。
- PF-DR-3: 一括追加は原子的に検証・保存する。owner/plannerのみ可。同一プロジェクト・分類・循環を検証し、重複追加は冪等。複数コアへの同時追加は両方を保持する。
- PF-DR-4: ドメインタブに関係図を表示する。コア・ビジネス・未分類を分け、実線は所属、破線は既存親子関係。拡大縮小・スクロール・定義を開く操作が可能。
- PF-DR-5: 一覧カードも複数所属を反映し、該当する各コアの下でビジネスを表示する。未所属ドメインも到達不能にしない。

従来のcore-domain-assignment.mdにある「親未設定だけを追加」「一つの親へ移動」の規則を本仕様で置き換える。新しい所属は既存の属性継承parent_idとは別に保持する。

## API / 保存
`GET /api/projects/:pid/domain-definitions` は `memberships` を追加。
`POST /api/projects/:pid/domain-definitions/:did/business-domains` に `{businessIds: string[]}`（1〜100件）を送る。旧単体追加APIも多対多として保持する。

SQLite起動DDLとPostgreSQL migration 016で同じテーブルを追加する。旧データの破壊的移行は行わない。
