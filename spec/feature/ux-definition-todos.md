# 概要のTODO: コアドメインとビジネスドメインをつなげる

2026-10-09 neco 指示で、Anatomia の実装整理TODOから切り替えた。
「ドメインと仕様書の関連付けのTODOがたくさん出るが、コアドメインとビジネスドメインをつなげれば解決する。
プログラムドメイン化は分離して運用でよい。」

## 利用者の操作

プロジェクトの概要を開くと、コアとビジネスのつながりに残っている TODO を読む。
名前で絞り込み、20件ずつ読み進める。
「ドメインで関連付ける」でドメインタブへ移り、該当ドメインのカードへ着地する
(`?tab=domains&focus=<ドメイン名>`)。つなげる操作はコアのカードを展開して行う
([domain-relations.md](./domain-relations.md))。TODO一覧自体は読み取り専用。

## 分類

`GET /api/projects/:pid/ux-design/definition-todos` はプロジェクト閲覧権限を確認し、
Pf の `domains` と `domain_memberships` から計算する (`shared/domain-link-todos.ts`)。

- PF-TODO-1 コアドメインが未定義: コアが 1 件も無いとき 1 件だけ出す。
- PF-TODO-2 分類が未定義: `definition_kind` が空のドメイン。
- PF-TODO-3 コアに未所属のビジネスドメイン: どのコアからも所属 (多対多の所属、または旧コア→ビジネスの親子) が無い。
- PF-TODO-4 ビジネスドメインが無いコア: 所属するビジネスが 1 件も無いコア。

並びは上の順、同じ分類内は名前順。

## 扱わないもの

実装コードのドメイン所属 (プログラムドメイン) は Anatomia 側で別に運用し、この一覧に混ぜない。
以前はここに Anatomia の `domain-organization` (未所属のコードシンボル・目的未定義・実装対応なし) を
並べていたが、コードシンボル単位で 1000 件を超え、コアとビジネスの整理を埋もれさせていた。
この一覧は Anatomia に依存しないため、Anatomia の停止で取得失敗にならない。

## 取得できない場合

DB 停止とプロジェクト不在はエラーとして表示する。未取得を空一覧としない。
