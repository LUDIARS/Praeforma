# 実装の整理TODOからUXを定義する

## 利用者の操作

UX設計ページを開くと、Anatomiaの解析根拠から整理TODOを読む。
UXがまだ関連付いていない項目を先に、分類・名前・参照ID順で表示する。
名前・ファイルで絞り込み、20件ずつ読み進める。
「この項目のUXを定義する」で、人間が利用者・状況・目的・成功条件を書く。
AIはユーザー価値を勝手に記入しない。項目名のみシナリオ名の初期値にする。
新規入力がある場合は、別TODOへの切替前に破棄の確認をする。

## 根拠と分類

`GET /api/projects/:pid/ux-design/definition-todos` はプロジェクト閲覧権限を確認し、
設定済みの Anatomia repo の `domain-organization` を読み取る。

- ドメイン未所属の実装: `unassignedCodeSymbols`。名前・ソース位置を表示する。
- 目的が未定義: ドメインの `purpose` が空。
- 実装との対応付けなし: `implementationStatus` が `missing`。

実装対応付けの欠落は、呼び出しの未配線・不要コードの証明ではない。
この段階でコアドメイン認定・コード削除・Anatomiaのゲート承認はしない。
途中導入の案件も、既存実装から人間のUX定義を始められる。

## 保存と再開

TODOの repo・種別・entity ID を含む参照をシナリオの `sourceRefs` に保存する。
該当するシナリオがあれば「UX定義を続ける」で開く。
UX保存を実装課題の解決と同一視せず、Anatomiaの根拠が残る項目を消さない。
既存の境界レビューと判断履歴を用いて、定義の追加・整理を進める。
TODO一覧自体は読み取り専用であり、複数人の担当予約機能ではない。

## スマホ

UX定義を初期ビューとし、キャンバスは別タブで開く。
新規・編集共通の複数行入力、1列配置、16pxの入力文字、44px以上のボタンを使う。
端末からの接続経路は別途利用範囲を確認する。認証なしの公開は自動設定しない。

## 取得できない場合

Anatomia未設定、repo未指定、通信・応答不正をエラーとして表示する。
未取得を空一覧としない。取得できた分類に項目がなくても、全体の配線検証完了とは表示しない。
