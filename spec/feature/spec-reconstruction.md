# レコンストラクションと変更履歴

- PF-RECON-1: 仕様画面から未統合フラグメントと構造化仕様をAIで統合する案を作る。ドメインは必須。資料内の指示をAIの実行命令として扱わない。
- PF-RECON-2: 変更前後と使ったフラグメントを確認して確定する。保留したフラグメントは理由とともに残す。統合できるフラグメントがない案は確定できない。同じ内容の既存仕様へ統合した場合も出典消費を記録してマイナーを上げ、内容が変わった仕様だけ前後差分を残す。
- PF-RECON-3: フラグメントまたは構造化仕様の追加ごとにパッチを増やす。レコンストラクション確定でマイナー、リリース記録でメジャーを増やす。
- PF-RECON-4: 各履歴から変化した仕様の前後を閲覧できる。統合前のフラグメントは削除しない。重複確定や古い入力の確定は拒否する。
- PF-RECON-5: 閲覧はプロジェクト参加者、再構築とリリース記録はowner/planner。既存のフラグメント追加権限を維持する。

既存データは0.0.0の基点。導入以前の履歴を推測しない。仕様行のversionと実装状況は別物として維持する。リリース記録はバージョンログへの記録であり、サービスの配布を行わない。
