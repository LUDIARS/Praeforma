# 断片整理TODO

## PF-FRAGMENT-TODO-1: 整理の入口

プロジェクト概要のTODOに、未整理の断片を体系へ整理する項目と件数を表示する。
体験設計のTODOとは独立して取得し、Anatomiaの設定や取得失敗に左右されない。
項目から仕様タブの断片一覧と **再構築（レコンストラクション）** を開ける。
開くだけでは案生成・仕様変更は実行しない。

## PF-FRAGMENT-TODO-2: 完了の根拠

未整理とは、確定済み再構築の統合元に記録されていない断片を指す。
実装済みかどうかとは独立する。生成しただけの案、保留された断片、失敗した確定では完了しない。
確定時に統合した分だけ件数が減る。元の断片は履歴として保持する。
TODOを別テーブルへ複製せず、手動の完了チェックも設けない。
件数は一覧のページ数・再構築の入力上限によらず全件を集計する。

## PF-FRAGMENT-TODO-3: 権限と表示

`GET /api/projects/:pid/spec-fragments/cleanup-todo` は既存のプロジェクト閲覧権限と削除状態を検査し、
`{ pendingCount: number, canReconstruct: boolean }` を返す。
再構築の生成・確定権限は既存どおりowner/plannerのみ。閲覧者にも整理状況と断片への入口を表示する。
読み込み中・取得失敗・未整理0件を区別し、失敗時には再取得できる。
断片追加と再構築確定後にキャッシュを無効化する。
