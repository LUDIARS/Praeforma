# 断片スプリント

## 目的

2026-10-14 neco 指示 (Discord Session フォーラム「Ludellus-Native」):

> Ludellus系はすべてセッションで指示された断片仕様をPfにフラグメントとして登録する
> スプリント作成してチェックし、まとまった時点で体系化する。

デファードプランニング (spec/feature/deferred-planning.md) の運用単位として、断片をスプリントに束ね、
その単位で実装状態を確認し、まとまった時点でそのスプリントの断片だけを再構築 (体系化) する。

## 用語

- **スプリント (sprint)**: 同じ時期・同じ目的で確認する断片の束。プロジェクト単位。
- **チェック**: スプリント内の各断片の実装状態 (未確認 / 未実装 / 実装済) と確認根拠を見て更新すること。
  実装状態は既存の断片の実装状態 (PF-FRAGMENT) をそのまま使い、スプリント側に複製しない。
- **まとまった**: スプリント内の未体系化の断片がすべて実装済になった状態。
- **体系化**: 既存のレコンストラクション。スプリント指定時は入力断片をそのスプリントの未体系化断片に限る。

## 要件

| ID | 内容 |
| --- | --- |
| PF-SPRINT-1 | スプリントは名前 (必須) と狙い (任意) を持ち、プロジェクトに属する。作成時に断片を指定できる。 |
| PF-SPRINT-2 | 断片は同時に 1 つのスプリントにだけ属する。別スプリント所属・別プロジェクトの断片の追加は拒否する。 |
| PF-SPRINT-3 | スプリントから断片を外せる。断片自体・実装状態・版履歴は変えない。体系化済の断片は外せない (出典を保つ)。 |
| PF-SPRINT-4 | 一覧・詳細は件数 (全体・実装済・未実装・未確認・体系化済) と段階 (空 / 確認中 / まとまった / 体系化済) を返す。段階は保存せず毎回計算する。 |
| PF-SPRINT-5 | 再構築の生成はスプリント ID を任意で受け、指定時はそのスプリントの未体系化断片だけを入力にする。確定時の元データ変更確認も同じスプリントの材料と比べる。別プロジェクトのスプリントは 404。 |
| PF-SPRINT-6 | 「まとまった」以外でも体系化は実行できる (デファードプランニングは実装済を体系化の前提にしない)。画面は未実装の件数を示して注意する。 |
| PF-SPRINT-7 | 閲覧は全ロール、作成・断片の追加/除外は断片を編集できるロール、体系化は従来どおり owner / planner。 |
| PF-SPRINT-8 | どのスプリントにも属さない未体系化の断片を一覧でき、スプリントへ追加できる。 |

## 段階の計算

`pending` = スプリント内で `spec_reconstruction_fragments` に出典記録が無い断片。統合 (integrated) も棄却 (rejected) も処理済として数える。

- 空: 断片 0 件
- 体系化済: 断片 1 件以上かつ pending 0 件
- まとまった: pending 1 件以上かつ pending がすべて実装済
- 確認中: それ以外

## データ

spec/schema/spec-sprints.md を正本とする。

## API (`/api/projects/:pid/spec-sprints`)

- `GET /` スプリント一覧 (新しい順) と件数・段階、`canEdit`。
- `POST /` `{ title, goal?, fragmentIds? }` 作成。
- `GET /unassigned` どのスプリントにも属さない未体系化断片 (最大 200 件)。
- `GET /:sid` スプリントと所属断片 (断片の全項目 + `reconstructed`)。
- `POST /:sid/fragments` `{ fragmentIds }` 追加。
- `DELETE /:sid/fragments/:fid` 除外。
- 体系化は `POST /api/projects/:pid/spec-versions/reconstructions` に `{ sprintId }` を渡す。

## 画面

仕様画面の種類に「スプリント」を追加する。スプリントの作成、件数と段階の表示、断片のチェック
(既存の断片カードで実装状態を更新)、未所属断片の追加、断片の除外、「このスプリントを体系化」を置く。
体系化の案は従来の再構築パネルで確認・確定する。

## やらないこと

- スプリントの期間・期限・担当の管理 (タスクの正本は Actio)。
- 体系化の自動実行。確定は従来どおり人が案を見て行う。
