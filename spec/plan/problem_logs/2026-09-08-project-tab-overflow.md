# プロジェクトのタブが増えて見える

- Date: 2026-09-08
- Area: ProjectTabs / プロジェクトメニュー

## Summary

necoから「タブが増殖した」と報告。4タブ＋その他を導入した後の表示回帰として扱う。

## Evidence

- main 571d5d3 の ProjectTabs.tsx は6件を定義し、4件を表示、残りをdetails配下へ常時描画していた。
- project-tabs.css は格納メニューに常時display: gridを指定し、非表示をブラウザのdetails実装に委ねていた。
- 操作用ブラウザの接続が無いため実画面の再現は未確認。タブ定義自体の重複は確認されていない。

## Cause

初回は閉じたdetails内の表示制御とCSSの組合せによる露出を疑ったが、PR 1506反映後にも再発したため、この仮説では説明できなかった。

再報告の操作は「ドメイン」「UX/ゴール」「概要」の切替。**根本原因は未確定のまま。**

調査中にProjectShowPage.tsxで同じ親の兄弟要素ProjectTabs・ProjectUxGoal・DomainDefinitionsPanelが全てkey={pid}となっている点に気付いたが、これは症状の原因ではない。Reactは配列やリストではない静的なJSX子要素を**キーではなく位置(スロット)で対応付ける**ため、静的子要素間でキーが重複しても対応付けは衝突しない。この位置ではkeyは「プロジェクト変更時にそのスロットを作り直す」ヒントとしてのみ働く。同ファイルのActorRegistration・SceneRegistration・SpecRegistrationは現在もkey={pid}のままだが、同じ理屈で問題は起きていない。

したがってタブバーが複数現れる症状の原因は別にある。次の調査は実画面で行い、重複しているDOMがProjectTabsのnavなのか、それとも本体側の静的ビルド由来の古いマークアップなのかを最初に切り分ける。ビルド成果物の混在(Follow-up参照)も候補として残っている。

## Fix Requirements

開閉をReactで管理し、閉じたメニューは描画しない。通常は4件＋その他とし、残りの項目と表示4件は重複させない。選択時の先頭移動とURLからの復元を維持する。

## Verification

Web型チェックとAnatomia verifyは通過。単体・統合・起動テストはこのセッションでは実行していない。

Revisorの確認対象: 初期表示・シーン/仕様の直接URL・その他からの繰り返し切替・戻る/進むで通常タブが4件、開いたメニューと合計6件で重複しないこと。Escapeとフォーカス離脱でメニューが消えること。狭い画面でもその他が別行のタブ一覧として露出しないこと。

再発分の必須確認: 今回のキー変更は原因に対する修正ではなく可読性の整理であるため、**症状が残っている前提で**実画面を確認する。概要→ドメイン→UX/ゴール→概要を繰り返し、プロジェクトメニューのnavが常に1個であること。各クリックでURLのtabと表示内容が一致すること。その他で項目を先頭に移した後と、戻る/進むでも同じ確認を行う。別プロジェクトへの移動で入力状態を引き継がないこと。

症状が再現した場合は、開発者ツールで重複したnav要素のDOMを採取し、Reactが描画したものか静的HTML由来かを確認してから原因を再特定する。

## Follow-up

マージ後に本体の静的画面をビルドして反映する。実画面確認で症状が残る場合は表示箇所を特定して再調査する。
