# データスキーマと Cr の論理保存先を Pf で設計する

2026-09-08。neco の指示による。「Cr の保存領域」はデータごとの論理的な保存先を意味する。

追加指示: 今回の保存先 UI はユーザーデータ向け。マスターデータ専用の設計画面は `spec/tasks/2026-09-08-master-data-schema-designer.md` に独立した実装タスクを作成した。現 UI の master / user 分類だけで専用設計機能を実現済みとは扱わない。

## 実装内容

Praeforma のプロジェクト画面に「データ設計」を追加した。データセットと項目を作り、型・必須・主キー・参照関係・分類・保護方針を定義し、各項目の保存先を選択できる。

たとえば通知設定の boolean 項目を、Cr のプロジェクトキー・モジュール・列名へ対応付ける。表示名やメールは Cr の共通プロフィールへの参照として選ぶ。その他のデータにはサービス DB・ローカル・オブジェクトストレージの論理的な保存先名を記入する。未定の保存先は下書きとして残せる。

設計を保存しても Cr のテーブル作成・データ移動・権限変更は発生しない。Cr の領域一覧を実環境から取得する機能や、設計を実スキーマへ適用する機能は含まれない。認証・認可のレビュー指摘を解決し、適用時の権限と差分確認を整えてから扱う。

編集は owner / planner / designer / programmer、閲覧はプロジェクトメンバーに限定する。PostgreSQL と local mode の SQLite にプロジェクト単位で保存し、版番号を使った比較更新で同時編集の上書きを防ぐ。競合時は入力を保持し、最新の保存内容を確認できる。設計 JSON と保存先一覧 Markdown を書き出せる。

仕様: `spec/feature/data-design.md`。保存スキーマ: `spec/data/schema/data-design.md`。Cr レビュー: `spec/plan/2026-09-08-cr-auth-schema-review.md`。

## 受け入れ条件

- プロジェクトの「データ設計」から項目ごとの論理保存先を指定できる。
- 個人属性は user データ・保護必須・Cr 正本として設計する。
- Cr プロジェクト領域では 1 ユーザー 1 行、対応型、予約列名、列の重複割当を検査する。
- 他プロジェクトのメンバーでない利用者は閲覧・更新できず、閲覧ロールでは変更できない。
- 同時保存を 409 とし、通信失敗や競合で編集内容を消さない。
- 実データ・認証情報を設計に入力させず、設計の保存を Cr への適用として表示しない。

以上は実装契約であり、以下の静的確認以外を実行済みとするものではない。
